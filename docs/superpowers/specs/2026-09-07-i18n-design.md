# Локализация KeenSwitch (i18n)

Дата: 2026-09-07
Статус: утверждён

## Задача

Расширение целиком на русском: строки захардкожены в HTML, в TS-модулях и в
`manifest.config.ts`, у обеих страниц стоит `lang="ru"`. Инфраструктуры i18n нет.
Нужно вынести пользовательские тексты в каталоги переводов и поддержать шесть
языков.

## Набор языков

`en`, `ru`, `uk` (украинский), `pl`, `de`, `tr`.

Ориентир — не мировые топ-языки, а локализация самого KeeneticOS: веб-интерфейс
роутера переведён на 13 языков (en, da, fi, fr, de, it, pl, pt, ru, es, sv, tr,
uk). Переводить расширение на язык, на котором пользователь не может открыть
панель роутера, смысла нет. Из этих 13 взяты реальные рынки Keenetic: Россия,
Украина, Турция (отдельный домен keenetic.com.tr), Германия (юрлицо Keenetic
GmbH, Оффенбах), Польша. Остальные (fr, it, es, pt) добавляются позже одним
файлом на локаль; скандинавские (da, fi, sv) пропущены — аудитория крошечная и
читает по-английски.

`default_locale` — **`en`**, не `ru`: иначе пользователь из непокрытой страны
увидит кириллицу вместо понятного текста.

## Механика выбора языка

Чистый нативный `chrome.i18n`. Язык интерфейса равен языку интерфейса Chrome,
переключателя внутри расширения нет.

Известный компромисс, принятый осознанно: `chrome.i18n` не поддерживает смену
языка в рантайме. Русскоязычные пользователи на англоязычном Chrome получат
английский интерфейс вместо нынешнего русского. Альтернатива (селектор языка в
настройках поверх `_locales`) рассмотрена и отклонена в пользу простоты.

## Архитектура

### 1. Каталоги переводов

`public/_locales/{en,ru,uk,pl,de,tr}/messages.json`.

Vite копирует содержимое `public/` в корень `dist/` как есть — отдельной
настройки сборки не требуется. В `manifest.config.ts` добавляется
`default_locale: 'en'`.

`name` остаётся литералом `'KeenSwitch'`: это бренд, он одинаков во всех
витринах Store и не переводится. Через `__MSG_appDesc__` идёт только
`description`. `action.default_title` — тоже бренд, остаётся литералом.

### 2. Точка доступа — `src/lib/i18n.ts`

```ts
export function t(key: string, subs?: string | string[]): string
export function applyI18n(root: ParentNode): void
```

`t()` — тонкая обёртка над `chrome.i18n.getMessage`. **Обязательное требование:**
если `chrome?.i18n` недоступен, `t()` возвращает сам ключ и не бросает
исключение. Тесты выполняются в голом Node без глобального `chrome`, и без
этого фолбэка импорт `t()` в `keenetic.ts` уронит весь тестовый прогон.

`applyI18n(root)` проходит по DOM и подставляет тексты:

| Атрибут | Куда пишет |
| --- | --- |
| `data-i18n` | `textContent` |
| `data-i18n-title` | `title` |
| `data-i18n-aria-label` | `aria-label` |
| `data-i18n-placeholder` | `placeholder` |

Вместо захардкоженного `lang="ru"` в обоих HTML — установка в рантайме:
`document.documentElement.lang = chrome.i18n.getUILanguage()`.

### 3. Ошибки: `KeeneticError` переходит на ключи

Сейчас класс несёт готовую русскую прозу, и `tests/auth.test.ts:87` ассертит
точный текст `'Роутер отклонил логин и пароль'`.

Класс получает поля `key` и `detailKey` — машинно-опознаваемую идентичность
ошибки. `message` и `detail` резолвятся через `t()` в конструкторе:

```ts
throw new KeeneticError('auth', 'errAuthRejected', 'errAuthRejectedDetail');
```

Тесты переходят на ассерты по `error.key`. Это строго лучше нынешнего теста: он
перестаёт ломаться от правки формулировки.

`assertNoRciError(result, action)` принимает не подпись действия, а её ключ
(`actionSetPolicy`, `actionSaveConfig`).

Локализация происходит в месте выброса, а не на границе UI: `chrome.i18n`
одинаково работает в service worker и в попапе, локаль одна и та же, а диффа
получается втрое меньше, чем при проносе кодов через `chrome.runtime.sendMessage`.

Сырой текст ошибки от роутера (поле `message` из RCI-ответа) не переводится и
проходит насквозь как `detail` — это диагностика от устройства, а не наш текст.

### 4. Множественное число — обходится, а не решается

В `chrome.i18n` плюралей нет. Строка вида `Устройств: 5` в русском, украинском и
польском требует трёх форм. Тянуть `Intl.PluralRules` ради двух строк — оверкилл.

Все счётные строки остаются в форме «Подпись: N» с двоеточием: она грамматически
корректна во всех шести языках и не разваливается при переводе. Формулировки,
где число вшито в фразу, переписываются в эту форму.

### 5. `scripts/package.mjs`

Проверка `manifest.description.length > 132` после замены на `__MSG_appDesc__`
станет бессмысленной (длина строки-плейсхолдера — 15 символов), а лимит Chrome
Web Store действует **для каждой локали отдельно**.

Проверка переезжает на обход всех шести `_locales/*/messages.json`: падаем с
указанием конкретной локали и фактической длины, если чей-то `appDesc` перевалил
за 132 символа. Немецкий на это вполне способен.

## Тестирование

- `t()` без глобального `chrome` возвращает ключ — покрывается юнит-тестом.
- `tests/auth.test.ts` переводится с ассертов по русскому тексту на `error.key`.
- Новый тест целостности каталогов: во всех шести `messages.json` одинаковый
  набор ключей и совпадающее число плейсхолдеров `$N` — расхождение означает
  пустое место в интерфейсе у части пользователей.
- Проверка лимита 132 символа для `appDesc` в каждой локали (в `package.mjs`).
- `npm run typecheck` и `npm run build` проходят.

## Качество переводов

Черновые переводы всех шести локалей пишутся в рамках задачи. `en`, `ru`, `de`
считаются готовыми; `uk`, `pl`, `tr` требуют вычитки носителями до релиза —
машинный перевод в сообщениях об ошибках сетевого оборудования легко даёт
неловкие формулировки.
